AICV는 로컬 AI CLI 사용 로그(Claude Code, Codex, Gemini)를 근거로 "AI 활용 능력 이력서"를 만들어 공개 프로필로 유지하는 도구다. MCP 서버가 로그에서 증거 팩을 모으고, AI가 그걸로 이력서 초안을 쓰고, 포탈에 발행한다. 많이 썼다는 리더보드도, 시험을 쳤다는 자격증도 아닌 "실제 작업 로그가 역량을 증명한다"가 처음 잡은 방향이었다.

9월 초 며칠 동안 커밋이 몰렸고, 9월 14일에 이 저장소를 Tokenbill로 합친다는 공지를 올렸다. 그 사이에 정한 것들을 적는다.

## 재현해 보니 숫자가 문제였다

증거 팩만 있으면 누가 돌려도 비슷한 이력서가 나와야 한다. 그래서 사례 후보와 링크를 증거 팩에 넣은 뒤, 팩만으로 이력서를 다시 생성해 기존 예시와 나란히 놓아 봤다.

문장 구조는 거의 같았다. 달라진 건 숫자였다. 세션당 턴 수, 병렬 도구 호출 횟수, 셸 실행 횟수, 도구 실패율 같은 값이 두 버전에서 조금씩 달랐다. 집계 기간을 어떻게 잡느냐에 따라 움직이는 값이었다.

그걸 보고 기준을 바꿨다. 이력서 가이드에서 **활동량 측정치는 금지**하고, **만든 것과 산출물 수치만** 쓰게 했다. 스킬 몇 종, MCP 서버 몇 종, 파일 몇 개 변환, 프로젝트 몇 개 같은 것이다. 호출 횟수, 셸 실행 횟수, 턴 수, 토큰량, 실패율, 병렬 호출 수는 전부 뺐다.

이유는 가이드에 한 줄로 적었다. 자기 도구가 센 값이라 제3자에게 판단 기준이 없다. 내 도구가 "실패율 2%대"라고 말해도, 읽는 사람은 그게 좋은 건지, 무엇을 분모로 센 건지 알 수 없다. 이미 rubric 점수를 인용하지 말라는 규칙이 있었는데, 같은 이유를 원천 수치까지 넓힌 셈이다.

예시 이력서도 새 기준으로 다시 썼다. 숫자가 빠지니 문장이 심심해졌지만, 대신 틀릴 수 있는 곳도 줄었다. 재생성 예시는 따로 둘 이유가 없어져서 본 예시에 합쳤다.

숫자를 뺀 자리는 **기술 스택**이 채웠다. 로그에서 터치한 파일의 언어를 자동으로 모아 백엔드, 프론트엔드, 데이터, 인프라로 묶어 프로필에 보여준다. 이것도 자동 집계지만, "무엇을 다뤘는가"는 "얼마나 많이 했는가"보다 읽는 사람이 판단하기 쉽다.

비슷한 맥락으로 프로필 하단의 "데이터 한계" 섹션도 걷어냈다. 한계를 설명하던 항목들이 대부분 이미 표시하지 않는 지표에 관한 것이었다. 투명성 고지는 푸터 한 줄로 남겼다.

## 토큰을 복사하지 않게

처음 설치 흐름은 이랬다. 포탈에서 업로드 토큰을 발급받고, 저장소를 clone하고, 토큰을 붙여 MCP를 등록한다. 세 단계 모두 사용자가 뭔가를 복사해서 붙여야 했다.

이걸 **연결 코드** 방식으로 바꿨다. 대시보드에서 코드를 발급받고, AI 세션에서 "aicv 연결해줘, 코드 K7F3QZ"라고 말하면 끝난다. MCP의 `connect_aicv` 도구가 코드를 토큰으로 교환해 로컬에 저장한다.

코드 규칙은 이렇게 정했다.

- 6자리, 10분 유효, 1회용
- 사용자당 활성 코드는 하나. 새로 발급하면 이전 코드는 무효가 된다
- 혼동하기 쉬운 문자(I, L, O, 0, 1)는 빼고 만든다. 사람이 화면을 보고 입으로 불러주는 코드라서다
- 교환할 때 이미 토큰이 있으면 새로 만들지 않고 기존 토큰을 돌려준다. 새로 만들면 먼저 연결해 둔 다른 기기가 끊긴다

토큰 우선순위는 명령 인자, 환경변수, 저장된 자격증명 순으로 두어 기존 방식도 그대로 동작하게 했다. 대시보드에서 토큰 직접 등록은 "고급" 아래로 접었다. 같은 날 clone 단계도 없앴다. 이제 설치는 `npx` 한 줄이고, Claude, Codex, Gemini별 명령을 탭으로 나눠 보여준다.

며칠 뒤에는 출시 기본기로 계정 삭제, 약관, 연결 코드 방어를 붙였다. 연결 코드가 편한 만큼 공격받을 자리도 되기 때문이다.

## 합치기로 했다

9월 14일, AICV를 Tokenbill의 기능으로 통합한다는 공지를 README 맨 위에 올렸다. AI 비용 대시보드와 AI 활용 이력서를 한 서비스에서 제공하려는 것이다.

돌아보면 두 서비스는 처음부터 많은 걸 나눠 쓰고 있었다. 같은 로그를 읽고, 같은 로그인 방식을 쓰고, 프로필 주소도 Tokenbill 도메인 아래에 있었다. 사용자 입장에서는 MCP를 두 개 설치하고 계정을 두 번 연결할 이유가 없다.

저장소는 바로 닫지 않는다. 기존 설치 명령과 프로필은 이관이 끝날 때까지 그대로 동작하게 두었다. 이미 연결해 둔 사람이 어느 날 갑자기 안 되는 일은 만들지 않으려고 한다.

## 남은 것

이 글은 AICV 저장소의 마지막 정리에 가깝다. 숫자를 빼기로 한 기준과 연결 코드 방식은 Tokenbill로 옮겨 가서도 유지할 생각이다. 특히 앞의 것은, 자동으로 셀 수 있는 값일수록 이력서에 넣기 전에 한 번 더 의심해야 한다는 교훈으로 남았다.
